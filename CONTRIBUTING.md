# Contributing

Thank you for looking. This repository is a projection of a private literate
corpus, so a contribution here is a proposal against the documents the code
is generated from. Here is how to make one that can be received.

## Propose a change

1. Find the source. Any file whose first line is
   `@generated by x0k-tangle … from <doc> — DO NOT EDIT` is produced from the
   literate document named in that line, under `knowledge/implementation/`.
   Edit that `.md` — the prose and the code chunks together — not the
   generated file. Hand-written modules (no such header) are edited directly.
2. Re-tangle so the committed code matches the document:

   ```sh
   cargo run -p x0k-tangle -- tangle knowledge/implementation/<area>/<doc>.md --workspace .
   ```

   Commit the document, its `.tangle-map.json` sidecar, and the regenerated
   output together.
3. Run `tools/ci`. It builds, tests, re-tangles every literate document, and
   fails on any difference from the tree. Green means the pair is in sync.
4. Open a pull request against this repository.

## What is refused

A pull request that edits an `@generated` file directly is refused by
`tools/x0k-guard-generated`, which runs on every pull request and names the
document to edit instead. There is no exception: the file would be
overwritten on the next projection anyway, and the change would be lost.

## What happens next

A maintainer receives an accepted change into the corpus, where it lands
under the corpus's own review, and it comes back to this repository with the
next projection. Until then the pull request stays open; the projection
commit that carries your change will reference the corpus revision it came
from in `PROVENANCE.json`.

This file is one of the *overlay* paths — files owned on this side of the
projection, listed under `overlay` in `PROVENANCE.json`. It is preserved as
found on every re-projection, so it can be edited here directly, by ordinary
pull request.
