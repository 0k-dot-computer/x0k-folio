# The Tangle Protocol

`x0k-tangle` is the substrate that makes [literate
programming](../../wiki/literate-programming.md "x0k:wiki/literate-programming") real in x0k. A literate document is markdown with named code chunks; the
tangler extracts those chunks and writes source files; an orthogonal
pipeline mechanism lets external codegens — theme tokens, service
adapters, future things we haven't invented yet — ride the same
discovery, dispatch, and freshness machinery.

This directory is the substrate explaining itself. Every Rust file
under `x0k-tangle/src/` is generated by a literate doc in this
directory; reading these pages tells you both *how the protocol works*
and *what the code in front of you is doing*. The substrate is
self-illustrating.

Two design docs sit upstream:

- [`x0k:design/literate-programming`](../../../decisions/design/corpus/literate-programming.md)
  — the experience-shape decision: code is authored as narrative,
  understanding is interactive, the document is the program.
- [`x0k:design/literate-pipelines`](../../../decisions/design/corpus/literate-pipelines.md)
  — the protocol contract: pipelines are plugins, identity tangling is
  itself a plugin, the registry is the dispatch surface.

The pages below are the implementation expressed as one cohesive
narrative. Read in order or jump to whatever you came for; each page
also tangles into a real `.rs` file the compiler consumes.

```
  dispatcher.md        → x0k-tangle/src/pipeline_runner.rs
  weave.md             → x0k-tangle/src/weave.rs
  bundle.md            → x0k-tangle-bundle/src/{lib.rs, bin/x0k-tangle.rs}
```

Each `<slug>.md` declares a `tangle:` block in its frontmatter naming
the crate + root, so re-tangling the workspace regenerates the same
`.rs` bytes the compiler is consuming right now. Edit a doc, run
`x0k-tangle workspace`, the source file updates. Edit the source file
directly and the next workspace pass will overwrite your edit — these
files are now *generated*. The `@generated` header at the top of each
`.rs` says where to look instead.

## The dispatch loop

The user-facing entry point is `tangle_document` (one doc) or
`tangle_workspace` (every literate root contributed by registered
plugins). The same loop services both modes — `tangle:` (identity
output) and `pipelines:` (transformed outputs):

```
parse document
  → split frontmatter, extract chunks, parse pipeline declarations
  → translate `tangle:` block into a synthetic identity-tangle
    PipelineDecl prepended to the declared pipelines
for each pipeline in document:
  → look up plugin in registry by `kind`
  → resolve `inputs:` map: each named chunk becomes a ChunkInput
    with <<refs>> already expanded
  → hash inputs + config for sidecar drift detection
  → call plugin.transform(ctx) → Vec<PipelineOutput>
  → for each output: prepend @generated header, atomic write,
    record (path, hash) in sidecar entry
write sidecar next to source as <stem>.tangle-map.json
```

Identity tangling and theme-codegen and whatever-codegen-comes-next
all flow through that same loop. The plugin contract is small (one
trait method) and tangle owns every concern that isn't the plugin's
direct responsibility.

One line shape is exempt from expansion. `<<!name>>` — the `!`
directly inside the brackets, indentation allowed — is the verbatim
escape: it tangles to the literal line `<<name>>` (indent kept) and
weaves to the same text with no anchor. It exists so a document can
show the reference syntax in what it produces, as the x0k-folio README
does when it teaches the `<<greet>>` line. The `!` prefix is reserved
by the reference scanner rather than forbidden by the fence parser's
name grammar; the scanner ([chunk.md](chunk.md)) says exactly which,
the resolver ([resolution.md](resolution.md)) emits the literal, and
the reverse path ([reverse-stitch.md](reverse-stitch.md)) re-escapes
a lifted `<<name>>` so the literal survives a round-trip.

Every module of the crate is projected from a chapter here; nothing under

the bare CLI `main.rs` (both from [crate.md](crate.md)). The map, module →

The pre-pipeline-protocol emitter that once defined `TangleMap` is gone;
its only surviving type moved into the reverse-stitch chapter, which was its
only reader.

The repository projector ([region-repo.md](region-repo.md)) ships more
than crates. A publication's `publishes` edge names each vocabulary
module it carries as `x0k:ontology-module/<name>` beside its
`x0k:software-module/<crate>` members (ADR
`x0k:architecture/ontology-modules` §6). The projector reads
`ontology/modules/<name>.ttl` for each, checks that every module the
file imports is also named (an import outside the selection refuses the
projection, naming both), refuses a module file that carries an
instance fact, and writes the file with an `owl:versionIRI` stamped
after the module fact — the version being the `entryPoint` crate's
manifest version, else the corpus revision — otherwise byte-identical.
`PROVENANCE.json` lists the modules and the version stamped; the README's
"What is here" table gains a row per module. Publishing `x0k-ontology`
without naming a module is an error, not a silent copy of the whole
vocabulary.

## Reading order

If you're trying to understand the protocol from scratch:

1. [parsing.md](parsing.md) — what a chunk is, how the info-string
   syntax encodes its attributes, how chunks accumulate by name +
   language variant.
2. [chunk-refs.md](chunk-refs.md) — language-aware `<<name>>`
   reference extraction; tree-sitter overlay that lets chunk
   bodies legitimately contain `<<x>>` strings as data without
   the resolver chasing them.
3. [resolution.md](resolution.md) — `<<chunk-ref>>` expansion with
   indentation preservation and cycle detection.
4. [pipeline.md](pipeline.md) — the `TanglePipeline` trait, the
   `PipelineRegistry`, the typed `PipelineContext` / `PipelineOutput`
   contract.
5. [identity-pipeline.md](identity-pipeline.md) — how identity
   tangling lives inside that trait surface as one plugin among many.
6. [dispatcher.md](dispatcher.md) — the user-facing entry points
   (`tangle_document`, `tangle_workspace`), sidecar bookkeeping,
   freshness, collision detection.
7. [weave.md](weave.md) — the HTML rendering side that turns the same
   literate doc into the page you might be looking at right now.
8. [bundle.md](bundle.md) — how first-party plugins compose into the
   canonical binary, why the bundle crate exists.

If you only want to find a specific surface: each page's frontmatter
declares its tangle target, so grep for the source file name in
`knowledge/implementation/tangle/` and you'll land on the doc that owns it.
