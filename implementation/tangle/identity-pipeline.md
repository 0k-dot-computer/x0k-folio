# Identity tangling as a plugin

The architectural payoff of the pipeline protocol is that *[identity
tangling](../../background/literate-programming.md "x0k:wiki/literate-programming") stops being a special case*. Before, `tangle:` and
`pipelines:` had separate code paths — separate parsers, separate
file writers, separate sidecar shapes. Now both flow through the same
dispatch loop because identity tangling is just one more plugin
registered with the registry.

`IdentityPipeline` is what makes that work. It implements
`TanglePipeline`; the dispatcher synthesizes a `PipelineDecl` for the
`tangle:` block and routes it through the same loop as theme-codegen
and any future pipeline.

## Module header

The doc-comment captures the synthesis trick so future readers don't
have to re-derive it: the `tangle:` block isn't a separate concept,
it's the shorthand for "run the identity-tangle pipeline."

<a name="chunk-module-header"></a><sub>[`src/identity_pipeline.rs`](../../crates/x0k-tangle/src/identity_pipeline.rs) · `#module-header`</sub>

```rust {#module-header}
//! Identity tangling expressed as a [`TanglePipeline`].
//!
//! In the layered protocol, the `tangle:` frontmatter block is the
//! shorthand for "run the identity-tangle pipeline on this doc". The
//! dispatcher in [`crate::pipeline_runner`] synthesizes a [`PipelineDecl`]
//! for it before dispatch, so identity tangling rides the same code path
//! as every other pipeline.
//!
//! [`PipelineDecl`]: x0k_folio::colophon::PipelineDecl
//!
//! ## What the plugin does
//!
//! - Reads the `tangle:` config from `ctx.config`: `{ "crate": "...",
//!   "root": "...", "roots": { lang: path, ... } }` (all optional; crate
//!   may be absent for repo-root tangle targets).
//! - Walks `ctx.all_chunks` to find chunks that aren't fragments (i.e.
//!   chunks referenced by `<<name>>` from another chunk) and aren't
//!   media/`from=` chunks.
//! - For each top-level chunk, resolves its output path:
//!   - `file=<path>` attribute on the chunk → that path under crate dir
//!     (or workspace root when no crate is set)
//!   - else the `roots:` entry for the chunk's fence language, when the
//!     doc declares per-language roots (the bilingual form)
//!   - else falls back to `root:` from the config
//! - Expands `<<refs>>` recursively (via [`crate::resolve::expand_chunk`],
//!   or its language-pinned sibling for per-language roots, over an
//!   ephemeral [`crate::parser::ParsedDocument`]).
//! - Returns one [`PipelineOutput`] per distinct target file, with the
//!   comment style resolved from the output's name and extension.
//!
//! ## Header
//!
//! The dispatcher prepends the standard `@generated by x0k-tangle
//! (pipeline: identity-tangle) from <source> — DO NOT EDIT.` header
//! using the comment style on each output. `resolve_comment_style`
//! picks that style from two sources, most specific first: the
//! document's own `comment_styles:` declaration, then the built-in
//! table in `comment_style_for_path`. The table matches the output's
//! file *name* first (`Makefile`, `.gitignore` and friends have no
//! extension for `Path::extension` to find), then its lowercased
//! extension. Anything still unmatched gets `//` line comments and a
//! `tangle.comment_style.unknown` warning.
//!
//! ## Declaring a style
//!
//! A document whose output language the table does not know declares
//! the marker itself, in the identity pipeline's `config:`:
//!
//! ```yaml
//! x0k:
//!   pipelines:
//!     - kind: identity-tangle
//!       config:
//!         root: analysis/fit.jl
//!         comment_styles:
//!           jl: "#"            # a line marker
//!           ml: ["(*", "*)"]   # a block open/close pair
//!           bin:               # null — write no header at all
//! ```
//!
//! Keys match the way the table matches: exact file name first, then
//! lowercased extension. A declared entry wins over the table, so a
//! document can also *correct* a mapping — `.pl` read as Prolog rather
//! than Perl, say — without waiting for a release of this crate.
//!
//! ## Spacing the output
//!
//! Top-level chunks are concatenated with nothing between them, which
//! is fine for Rust and wrong for a language whose style checker counts
//! blank lines. `join:` declares the separator, as a number of blank
//! lines for the whole document or a map keyed the same way
//! `comment_styles:` is:
//!
//! ```yaml
//! x0k:
//!   pipelines:
//!     - kind: identity-tangle
//!       config:
//!         root: pymc_extras/model.py
//!         join: 2              # PEP 8 E301/E302
//!         # or, for a document with per-language `roots:`
//!         # join: { py: 2 }
//! ```
//!
//! Absent, it is zero, which is the concatenation every document in the
//! corpus was written against.
```

## The kind constant + config shape

`IDENTITY_KIND` is the sentinel string the dispatcher looks up in the
registry. Everything that surfaces the kind to operators (sidecar
records, `@generated` headers, error messages) goes through this
constant, so the operator-visible name is single-sourced.

<a name="chunk-kind-and-config"></a><sub>[`src/identity_pipeline.rs`](../../crates/x0k-tangle/src/identity_pipeline.rs) · `#kind-and-config`</sub>

```rust {#kind-and-config}
/// Sentinel kind for the identity-tangle pipeline. Surfaced in
/// `@generated` headers and in sidecar `pipelines[].kind`.
pub const IDENTITY_KIND: &str = "identity-tangle";

/// Untyped JSON shape for the synthesized config. Mirrors
/// `x0k_folio::colophon::TangleConfig` minus serde renames, plus
/// `comment_styles` — the escape hatch the mirrored type does not
/// carry yet.
#[derive(Debug, Default, Deserialize)]
struct IdentityConfig {
    #[serde(default, rename = "crate")]
    crate_name: Option<String>,
    #[serde(default)]
    root: Option<String>,
    /// Per-language roots (fence language → output path) for bilingual
    /// docs. Empty for single-target docs.
    #[serde(default)]
    roots: BTreeMap<String, String>,
    /// Author-declared header styles, keyed by output file name or
    /// lowercased extension. A null value means "write no header at
    /// all" — the `json` case generalized to any syntax that cannot
    /// host a comment. Entries beat the built-in table.
    #[serde(default)]
    comment_styles: BTreeMap<String, Option<CommentStyleDecl>>,
    /// Blank lines placed between consecutive top-level chunk
    /// expansions in one output. Absent means zero — what every
    /// document in the corpus was written against.
    #[serde(default)]
    join: JoinDecl,
}

/// How many blank lines separate top-level chunks in an output. A bare
/// integer speaks for every output of the document; a map keys them by
/// output file name or lowercased extension, the same way
/// `comment_styles` does, so a bilingual document can space its Python
/// two lines apart and leave its Rust alone.
#[derive(Debug, Clone, Deserialize)]
#[serde(untagged)]
enum JoinDecl {
    /// `join: 2`
    Uniform(usize),
    /// `join: { py: 2 }`
    PerOutput(BTreeMap<String, usize>),
}

impl Default for JoinDecl {
    fn default() -> Self {
        JoinDecl::Uniform(0)
    }
}

/// One author-declared style. A bare string is a line marker; a
/// two-element sequence is a block open/close pair. Untagged, so the
/// YAML reads the way the marker looks.
#[derive(Debug, Clone, Deserialize)]
#[serde(untagged)]
enum CommentStyleDecl {
    /// `jl: "#"`
    Line(String),
    /// `ml: ["(*", "*)"]`
    Block([String; 2]),
}
```

The `crate` field is renamed (Rust reserves the bare identifier) but
the JSON wire name stays `crate` to match how `tangle:` is authored
in the frontmatter. `roots` is a `BTreeMap` for deterministic
iteration; output *order* still follows chunk declaration order, so
the map's sorting never shows up in emitted bytes.

`comment_styles` is the one field with no counterpart in
`TangleConfig`. The dispatcher synthesizes the identity config from
the `tangle:` block's three known keys, so a document reaches this
field by declaring the pipeline explicitly under `pipelines:` instead
of using the `tangle:` shorthand. Everything downstream of the config
JSON already carries it; teaching the `tangle:` shorthand to forward
a `comment_styles:` submap is a change to the frontmatter walk and
the synthesis site, not to this plugin.

## The transform implementation

This is the bulk of the file. Walk it from the outside in:

1. Deserialize the `tangle:` config into typed shape.
2. Identify "fragment chunks" — chunks referenced from another chunk
   via `<<name>>`. Fragments are not top-level outputs; their content
   ends up inlined at their call sites instead. An escaped `<<!name>>`
   is literal text ([`resolution.md`](resolution.md)) and makes
   nothing a fragment.
3. For each top-level chunk (non-fragment, non-media, non-`from=`),
   determine its target file path (via `file=`, the per-language
   `roots:` entry, or the config's `root:`), expand its body via
   `expand_chunk`, and append to the right output bucket.
4. Compose each bucket into a single string and return one
   `PipelineOutput` per bucket with comment style derived from
   extension.

A doc with per-language `roots:` changes the grain of step 3: every
language *variant* of a top-level chunk is its own output, routed to
its language's root and expanded with reference resolution pinned to
that language. A single-target doc keeps the historical grain — the
first variant speaks for the name — so every existing doc tangles to
the same bytes it did before `roots:` existed. The same gate applies
to fragment collection: per-language docs scan every variant's body
for `<<refs>>` (the Gallowglass body's fragments are as real as the
Rust body's); single-target docs scan only the first, preserving
their recorded output hashes.

The two `literate_roots` entries and the style resolution in
`resolve_comment_style` round out the trait impl. Style resolution is
the one step in the compose loop that can fail: a malformed declared
marker is a config error, reported rather than written into a file.

<a name="chunk-transform-impl"></a><sub>[`src/identity_pipeline.rs`](../../crates/x0k-tangle/src/identity_pipeline.rs) · `#transform-impl`</sub>

```rust {#transform-impl}
impl TanglePipeline for IdentityPipeline {
    fn kind(&self) -> &str {
        IDENTITY_KIND
    }

    fn literate_roots(&self) -> Vec<&'static str> {
        // Production code literate substrate (one subdir per crate /
        // subsystem). Officina's literate docs live under
        // `knowledge/implementation/0k.computer/`; future crates add siblings.
        vec!["knowledge/implementation"]
    }

    fn transform(&self, ctx: &PipelineContext) -> Result<Vec<PipelineOutput>, PipelineError> {
        let config: IdentityConfig = serde_json::from_value(ctx.config.clone())
            .map_err(|e| PipelineError::invalid_config(e.to_string()))?;

        let crate_dir = config
            .crate_name
            .as_deref()
            .map(|c| ctx.workspace_root.join(c));
        let root_path = config.root.as_deref().map(PathBuf::from);
        let per_lang = !config.roots.is_empty();

        // Build the same fragment-set the legacy emitter does: any
        // chunk referenced by `<<name>>` from another non-media,
        // non-from chunk. Those are composition fragments and should
        // not be emitted as standalone top-level outputs. Walk in
        // declaration order so we visit each chunk once. Per-language
        // docs scan every variant; single-target docs only the first
        // (byte-stability for their recorded outputs).
        let mut fragment_chunks: HashSet<String> = HashSet::new();
        for name in ctx.chunk_order {
            let Some(variants) = ctx.all_chunks.get(name) else {
                continue;
            };
            let scan = if per_lang {
                &variants[..]
            } else {
                &variants[..variants.len().min(1)]
            };
            for chunk in scan {
                if chunk.is_media || chunk.is_from_ref() {
                    continue;
                }
                let body = chunk.combined_body();
                for r in find_chunk_refs_aware(&body, chunk.lang.as_deref()) {
                    // `<<!name>>` is literal text, not a composition.
                    if !r.escaped {
                        fragment_chunks.insert(r.name);
                    }
                }
            }
        }

        // Group top-level chunks by their resolved target path,
        // preserving declaration order within each group (matches the
        // legacy emitter's HashMap insertion order, which is
        // declaration order because we iterate chunk_order).
        let mut outputs: Vec<(PathBuf, Vec<(String, String)>)> = Vec::new();

        // We need a `ParsedDocument` to drive `expand_chunk`. Build a
        // synthetic one over the chunk map we already have — the
        // expander only consults `chunks` + `chunk(name)`, so we don't
        // need to round-trip through the parser.
        let parsed = synthetic_parsed_doc(ctx.all_chunks, ctx.chunk_order, &config);

        for name in ctx.chunk_order {
            let Some(variants) = ctx.all_chunks.get(name) else {
                continue;
            };
            if fragment_chunks.contains(name) {
                continue;
            }
            let emit = if per_lang {
                &variants[..]
            } else {
                &variants[..variants.len().min(1)]
            };
            for chunk in emit {
                if chunk.is_media || chunk.is_from_ref() {
                    continue;
                }

                // Target resolution, most specific first: the chunk's own
                // `file=`, the doc's per-language root for this variant's
                // fence language, the single `root:`. A variant with none
                // of the three is not a tangle output.
                let lang_root = chunk
                    .lang
                    .as_deref()
                    .and_then(|l| config.roots.get(l))
                    .map(PathBuf::from);
                let relative = if let Some(ref file) = chunk.file_target {
                    file.clone()
                } else if let Some(root) = lang_root {
                    root
                } else if let Some(ref root) = root_path {
                    root.clone()
                } else {
                    continue;
                };
                let target = if let Some(ref cd) = crate_dir {
                    cd.join(&relative)
                } else {
                    ctx.workspace_root.join(&relative)
                };

                let expanded = match (per_lang, chunk.lang.as_deref()) {
                    (true, Some(lang)) => expand_chunk_lang(&parsed, name, lang),
                    _ => expand_chunk(&parsed, name),
                }
                .map_err(|e| {
                    PipelineError::transform_failed(format!(
                        "expanding chunk `{name}`: {e}"
                    ))
                })?;

                // Append to existing target entry (preserving declaration
                // order) or create new one.
                if let Some(entry) = outputs.iter_mut().find(|(p, _)| p == &target) {
                    entry.1.push((name.clone(), expanded));
                } else {
                    outputs.push((target, vec![(name.clone(), expanded)]));
                }
            }
        }

        let mut result = Vec::with_capacity(outputs.len());
        for (file_path, chunk_expansions) in outputs {
            let blanks = resolve_join(&file_path, &config.join)?;
            let mut content = String::new();
            for (i, (_name, expanded)) in chunk_expansions.iter().enumerate() {
                if i > 0 {
                    for _ in 0..blanks {
                        content.push('\n');
                    }
                }
                content.push_str(expanded);
                content.push('\n');
            }

            let style = resolve_comment_style(&file_path, &config.comment_styles)?;
            // Emit absolute path; dispatcher does no further joining
            // when path is absolute.
            result.push(PipelineOutput {
                path: file_path,
                content: content.into_bytes(),
                header_comment_style: style,
            });
        }

        Ok(result)
    }
}
```

Two non-obvious choices deserve naming:

- **Vec, not HashMap, for output grouping.** A HashMap would scramble
  declaration order across runs; the dispatcher needs deterministic
  output order so the sidecar hashes stay stable. The linear scan
  with `iter_mut().find` is fine because docs rarely have more than
  a handful of distinct output files.
- **Synthetic ParsedDocument.** `expand_chunk` was built to operate
  on a `ParsedDocument`, but we don't need to re-parse the source —
  the chunks are already in `ctx.all_chunks`. Wrap them in a
  synthetic doc that satisfies the expander's interface. Cheap
  trick, avoids duplicating the expander.

    }

## Joining top-level chunks

A document whose output has more than one top-level chunk gets those
chunks concatenated, in declaration order, each terminated by a single
newline. That is the whole join, and for Rust it has never been worth a
thought: `rustfmt` is not run over generated files here, and nothing in
the language cares whether two `impl` blocks are separated by a blank
line.

Python cares. A PyMC maintainer measured what that means: `ruff-check`
in their pre-commit selects `E`, and E301/E302 want one or two blank
lines before a nested or top-level definition. A module tangled from
two chunks arrives with none, the formatter that would fix it is
forbidden on `@generated` files, and so every literate module they ship
fails pre-commit forever. They found a workaround — open every chunk
after the first with blank lines — and it works, because a *leading*
blank line survives into the output while a *trailing* one does not.
That asymmetry is real, it is undocumented, it is invisible in most
Markdown editors, and a second evaluator hit it independently and also
found it only by experiment. It is a trick, and a substrate whose
correct use is a trick is a substrate that teaches the wrong thing.

`join:` is the separator, declared rather than smuggled in as
whitespace:

```yaml
x0k:
  pipelines:
    - kind: identity-tangle
      config:
        root: pymc_extras/model.py
        join: 2                    # PEP 8: two blank lines between top-level chunks
```

A bare integer speaks for every output of the document. A map keys them
the way `comment_styles:` does — output file name first, then lowercased
extension — so a document with per-language `roots:` can space its
Python two lines apart and leave its Rust exactly as it was:

```yaml
        join: { py: 2 }
```

<a name="chunk-join-resolution"></a><sub>[`src/identity_pipeline.rs`](../../crates/x0k-tangle/src/identity_pipeline.rs) · `#join-resolution`</sub>

```rust {#join-resolution}
/// Most blank lines a document may ask for between chunks. Real values
/// are zero, one and two; the cap bounds what a typo in a config can
/// push into a file.
const MAX_JOIN_BLANK_LINES: usize = 8;

/// Blank lines to place between consecutive top-level chunks in one
/// output, resolved most-specific-first: the output's file name, its
/// lowercased extension, then zero. A bare `join:` integer answers for
/// every output without consulting the keys at all.
fn resolve_join(path: &std::path::Path, declared: &JoinDecl) -> Result<usize, PipelineError> {
    let blanks = match declared {
        JoinDecl::Uniform(n) => *n,
        JoinDecl::PerOutput(map) => style_keys(path)
            .iter()
            .find_map(|k| map.get(k).copied())
            .unwrap_or(0),
    };
    if blanks > MAX_JOIN_BLANK_LINES {
        return Err(PipelineError::invalid_config(format!(
            "join: {blanks} blank lines for {} exceeds the cap of {MAX_JOIN_BLANK_LINES}",
            path.display()
        )));
    }
    Ok(blanks)
}
```

### Why a declaration, and why zero by default

Three shapes were on the table, and the constraint that decided between
them is that **no file already in the tree may change**. A projection
that shifts under a corpus of 1130 generated outputs is not a fix; it is
a diff nobody asked for riding into every working copy that re-tangles,
which is exactly the shape of the format-only reversion this repository
spent a night chasing.

*Preserve trailing blank lines symmetrically* is the honest fix and the
one this section does not perform, because it cannot be performed from
here. The stripping happens in the parser — every fence body is
`trim_end`-ed as it is captured — so by the time a chunk reaches this
plugin the trailing blanks are already gone, and no join can put back
information that was discarded two modules upstream. It is also the
option with the widest blast radius: it changes the meaning of every
fence in the corpus that happens to end with a blank line, and it does
so silently.

*A language-aware default* — two blank lines for `.py` because PEP 8
says so — is the nicest thing to read in a bug report and the worst
thing to ship. It cannot tell a document written yesterday from one
written before the rule existed, so it rewrites the existing Python
outputs in the tree whether or not their authors want it. Fourteen
outputs across this corpus are Python; fourteen silent rewrites is a
small number and a bad precedent.

*A declaration* leaves every existing document producing the bytes it
produced before, because an absent `join:` is `Uniform(0)` and
`Uniform(0)` walks the same push-and-newline loop the plugin always
walked. Nothing is inferred, the setting is greppable, and the reader
of a Python module can find out why it is spaced the way it is by
opening the document that made it.

### What this does not reach

Two things, stated so the next reader does not have to measure them
again.

A document that composes through a single `#root` chunk — the
overwhelmingly common shape here — has exactly one top-level chunk, so
`join:` never fires. That document already controls its spacing: blank
lines written *between* `<<refs>>` inside the root body are interior to
that body, survive the parser untouched, and land in the output
verbatim. Two blank lines between two refs give two blank lines in the
file. `join:` is for the other shape, where several chunks each name
their own target and the concatenation is the plugin's to decide.

And the trailing-blank asymmetry itself is routed around, not removed.
A chunk that ends in blank lines still loses them, and two fences
sharing a `#name` are still joined by a single newline. Both live in
the parser's `trim_end` and in `Chunk::combined_body`; the boundary is
noted where those are described, in [`chunk.md`](chunk.md).

## Resolving a style

Two sources, most specific first. A document's own declaration wins;
otherwise the built-in table speaks. The lookup keeps `None` (write no
header) distinct from "no entry", which is why the declared map is
`BTreeMap<String, Option<_>>` and not `BTreeMap<String, _>`: a
document that tangles a `.jsonl` fixture needs to say *suppress the
header*, and saying it must not read as saying nothing.

<a name="chunk-style-resolution"></a><sub>[`src/identity_pipeline.rs`](../../crates/x0k-tangle/src/identity_pipeline.rs) · `#style-resolution`</sub>

```rust {#style-resolution}
/// Resolve the header style for one output: the document's
/// `comment_styles:` declaration first, then the built-in table.
/// Fails only on a malformed declared marker — a config error the
/// author can see and fix, rather than bytes written into a file.
fn resolve_comment_style(
    path: &std::path::Path,
    declared: &BTreeMap<String, Option<CommentStyleDecl>>,
) -> Result<Option<CommentStyle>, PipelineError> {
    for key in style_keys(path) {
        let Some(entry) = declared.get(&key) else {
            continue;
        };
        return match entry {
            None => Ok(None),
            Some(CommentStyleDecl::Line(marker)) => {
                Ok(Some(CommentStyle::Line(intern_marker(marker)?)))
            }
            Some(CommentStyleDecl::Block([open, close])) => Ok(Some(CommentStyle::Block(
                intern_marker(open)?,
                intern_marker(close)?,
            ))),
        };
    }
    Ok(comment_style_for_path(path))
}

/// The keys one output path is looked up under, most specific first:
/// its exact file name — `Makefile` and `.gitignore` have no extension
/// for `Path::extension` to find — then its lowercased extension.
fn style_keys(path: &std::path::Path) -> Vec<String> {
    let mut keys = Vec::with_capacity(2);
    if let Some(name) = path.file_name().and_then(|n| n.to_str()) {
        keys.push(name.to_string());
    }
    if let Some(ext) = path.extension().and_then(|e| e.to_str()) {
        keys.push(ext.to_ascii_lowercase());
    }
    keys
}
```

## Interning declared markers

`CommentStyle` holds `&'static str`, which is right for a compile-time
table and wrong for a marker that arrives in a document's config and
dies with the call. Interning bridges the two. This table is the one
piece of process state in a plugin the protocol calls pure, and it is
worth being blunt about the trade: the alternative was widening
`CommentStyle` to owned strings, which would have rewritten every
`CommentStyle::Line("#")` construction in the theme codegen and the
dispatcher for a benefit that lives entirely in this file. The table
only memoizes — it cannot change what a run emits — and the distinct
markers a workspace uses number in the tens, so what leaks is bounded
by the marker vocabulary rather than by documents tangled. The length
cap keeps a malformed config from pinning something large.

<a name="chunk-marker-interning"></a><sub>[`src/identity_pipeline.rs`](../../crates/x0k-tangle/src/identity_pipeline.rs) · `#marker-interning`</sub>

```rust {#marker-interning}
/// Longest declared marker accepted. Real markers are one to three
/// bytes; the cap bounds what a malformed config can intern.
const MAX_MARKER_LEN: usize = 8;

/// Intern a declared marker into the `'static` slot [`CommentStyle`]
/// holds, deduplicating so repeats across documents cost nothing.
fn intern_marker(raw: &str) -> Result<&'static str, PipelineError> {
    if raw.is_empty() || raw.len() > MAX_MARKER_LEN || raw.contains(['\n', '\r']) {
        return Err(PipelineError::invalid_config(format!(
            "comment marker {raw:?} must be 1 to {MAX_MARKER_LEN} bytes on one line"
        )));
    }
    static MARKERS: OnceLock<Mutex<HashSet<&'static str>>> = OnceLock::new();
    let mut markers = MARKERS
        .get_or_init(|| Mutex::new(HashSet::new()))
        .lock()
        .unwrap_or_else(|poisoned| poisoned.into_inner());
    if let Some(interned) = markers.get(raw) {
        return Ok(interned);
    }
    let interned: &'static str = Box::leak(raw.to_string().into_boxed_str());
    markers.insert(interned);
    Ok(interned)
}
```

## The built-in table

The table earns its length by being the thing that stops being wrong
by accident. Every group below is a language family whose line comment
is *not* `//`, plus — new here — the C-family extensions written out
explicitly, so that a `.rs` file getting `//` is a decision the table
made rather than a default it fell through.

Names come first because the build files that most often need a `#`
header carry no extension at all.

<a name="chunk-comment-style-table"></a><sub>[`src/identity_pipeline.rs`](../../crates/x0k-tangle/src/identity_pipeline.rs) · `#comment-style-table`</sub>

```rust {#comment-style-table}
/// Map an output file to the comment marker its syntax accepts, or
/// `None` for a syntax that cannot host a comment at all (JSON), where
/// the header would corrupt the artifact. File name first, then
/// lowercased extension, then the warned `//` fallback.
fn comment_style_for_path(path: &std::path::Path) -> Option<CommentStyle> {
    let name = path.file_name().and_then(|n| n.to_str()).unwrap_or_default();
    match name {
        // Build, container and dotfile formats: no extension exists
        // for `Path::extension` to see, so the whole name is the key.
        "Makefile" | "makefile" | "GNUmakefile" | "Dockerfile" | "Containerfile"
        | "Justfile" | "justfile" | "Rakefile" | "Gemfile" | "Vagrantfile" | "Brewfile"
        | "Procfile" | "Caddyfile" | "Kconfig" | "CMakeLists.txt" | "meson.build"
        | ".gitignore" | ".gitattributes" | ".dockerignore" | ".npmignore"
        | ".editorconfig" | ".env" => return Some(CommentStyle::Line("#")),
        // A Jenkins pipeline is Groovy wearing no extension.
        "Jenkinsfile" => return Some(CommentStyle::Line("//")),
        _ => {}
    }
    let ext = path
        .extension()
        .and_then(|e| e.to_str())
        .unwrap_or_default()
        .to_ascii_lowercase();
    match ext.as_str() {
        // JSON has no comment syntax — a header would make the output
        // unparseable, and a tangled `.json` artifact exists to be read
        // back by a parser. Provenance still lives in the
        // `.tangle-map.json` sidecar.
        "json" => None,
        "css" | "scss" | "sass" | "less" => Some(CommentStyle::Block("/*", "*/")),
        // Markdown renders comments invisibly only in HTML form — the
        // same block style keeps the header out of the rendered page.
        "html" | "htm" | "xhtml" | "xml" | "xsl" | "xslt" | "svg" | "md" | "markdown" => {
            Some(CommentStyle::Block("<!--", "-->"))
        }
        // ML-family and Pascal-family block comments.
        "ml" | "mli" | "sml" | "pas" | "pp" | "dpr" => Some(CommentStyle::Block("(*", "*)")),
        // The `#` family: shells, scripting languages, config formats.
        // `.pl` is read as Perl, the commoner claimant; a Prolog
        // document declares `pl: "%"` to take the extension back.
        "py" | "pyi" | "rb" | "sh" | "bash" | "zsh" | "ksh" | "fish" | "toml" | "yaml"
        | "yml" | "nix" | "jl" | "r" | "pl" | "pm" | "ps1" | "psm1" | "psd1" | "ex"
        | "exs" | "eex" | "heex" | "cr" | "nim" | "tcl" | "tk" | "awk" | "cmake" | "mk"
        | "mak" | "make" | "dockerfile" | "gitignore" | "gitattributes" | "conf"
        | "cfg" | "service" | "desktop" | "gitconfig" => Some(CommentStyle::Line("#")),
        // Gallowglass (`.gls`) and methodology NF (`.nf`) share `--`; a
        // `//` header would be a syntax error in the tangled source.
        // Ada, VHDL, Elm and Haskell join them.
        "sql" | "lua" | "hs" | "lhs" | "gls" | "nf" | "elm" | "ada" | "adb" | "ads"
        | "vhd" | "vhdl" => Some(CommentStyle::Line("--")),
        // Lisps and their data languages.
        "lisp" | "lsp" | "cl" | "el" | "scm" | "ss" | "rkt" | "clj" | "cljs" | "cljc"
        | "cljd" | "edn" | "fnl" => Some(CommentStyle::Line(";")),
        // Erlang, Prolog under its unambiguous extensions, and TeX.
        "erl" | "hrl" | "escript" | "pro" | "prolog" | "tex" | "sty" | "ltx" => {
            Some(CommentStyle::Line("%"))
        }
        // Free-form Fortran takes `!` anywhere on the line.
        "f90" | "f95" | "f03" | "f08" | "f18" => Some(CommentStyle::Line("!")),
        // Fixed-form Fortran does not: a comment is a `C` in column 1,
        // which is exactly where the header goes.
        "f" | "for" | "ftn" | "f77" => Some(CommentStyle::Line("C")),
        // Visual Basic and its dialects.
        "vb" | "vbs" | "bas" | "frm" => Some(CommentStyle::Line("'")),
        // The C family, written out. These were correct before only
        // because the fallback happened to agree with them; saying so
        // is what lets the fallback become a warning.
        "rs" | "ts" | "tsx" | "mts" | "cts" | "js" | "jsx" | "mjs" | "cjs" | "json5"
        | "jsonc" | "c" | "h" | "cc" | "cpp" | "cxx" | "hpp" | "hh" | "hxx" | "cs"
        | "go" | "java" | "kt" | "kts" | "scala" | "swift" | "dart" | "php" | "zig"
        | "d" | "groovy" | "gradle" | "proto" | "sol" | "fs" | "fsi" | "fsx" | "ino"
        | "wgsl" | "glsl" | "hlsl" | "metal" | "vert" | "frag" | "geom" | "comp" => {
            Some(CommentStyle::Line("//"))
        }
        // Nothing matched. `//` is still the best single guess, but an
        // unlisted language arriving here is a bug report, not a
        // routine event, so it leaves a trace.
        _ => {
            tracing::warn!(
                path = %path.display(),
                extension = %ext,
                "tangle.comment_style.unknown"
            );
            Some(CommentStyle::Line("//"))
        }
    }
}
```

Two extensions are deliberately absent. `.m` is MATLAB (`%`),
Objective-C (`//`) and Mercury (`%`) at once, and `.v` is Verilog
(`//`) and Coq (`(* *)`); guessing either would replace a loud
fallback with a quiet wrong answer. They fall through to the warning,
which names the file and the extension, and the document that owns one
declares what it means.

## What the fallback still is

The fallback stays `//`, now warned. The three alternatives were real,
and each loses more than it gains:

- **Silence** is what this document shipped with, and it is what wrote
  `//` into a Julia file and said nothing. Not an option.
- **No header for unknown extensions** never corrupts a file, and that
  is its whole case. Against it: the `@generated … DO NOT EDIT` line
  *is* the edit protection. `tools/generated-drift`,
  `tools/fmt-churn-guard.py`, the receive path's refusal in
  `receive.rs`, and the `x0k-guard-generated` script the repository
  projector writes into published repos all find a generated file by
  grepping its first line for `@generated`. A headerless output is a
  file every one of those gates waves through — and unlike a broken
  header, nothing about it looks wrong. It trades a failure the author
  sees within seconds for one nobody sees for months.
- **Refusing to tangle** makes the author declare a style. It also
  turns every genuinely new extension into a hard stop, including the
  many where `//` is simply right, and it changes the tangler from
  something that always projects into something that can decline —
  during a release, on a corpus of thousands of documents, that is a
  large behavioral promise to break for a small class of files.

The warning is what makes the fallback honest rather than merely
convenient: `//` still goes in, the operator sees
`tangle.comment_style.unknown` with the path and the extension, and
`comment_styles:` is a one-line fix that does not wait on us. The
residual exposure is a language whose comment marker is not `//` and
whose author never reads the warning; the table above shrinks that set
to the ones nobody has written yet.

## Tests

The tests are unit-level: each verifies one extension maps to the
expected style, plus a sanity check on the kind constant and the
roots claim. Three groups carry the weight — the families whose
marker is not `//`, the name-keyed entries no extension can reach,
and the declared-style hatch in all four of its shapes (override a
known extension, supply an unknown one, suppress the header, name a
block pair). End-to-end identity-tangling behavior is exercised in
[`dispatcher.md`](dispatcher.md)'s tests where the dispatcher and
plugin run together.

The join tests are the exception to "unit-level": they drive
`transform` over a two-chunk Python document, because the thing under
test is the bytes of a whole output and asserting them anywhere else
would be asserting a paraphrase. The first of them pins the default
concatenation exactly. Every recorded output hash in the corpus rests
on those bytes, so that test is less a test than a fence.

        // A bilingual document spaces its Python and leaves its Rust as
        // it was; a file name beats an extension, as it does for styles.
        let decl = JoinDecl::PerOutput(BTreeMap::from([
            ("py".to_string(), 2),
            ("conftest.py".to_string(), 0),
        ]));
        assert_eq!(resolve_join(std::path::Path::new("a/m.py"), &decl).unwrap(), 2);
        assert_eq!(resolve_join(std::path::Path::new("a/m.rs"), &decl).unwrap(), 0);
        assert_eq!(
            resolve_join(std::path::Path::new("a/conftest.py"), &decl).unwrap(),
            0
        );
    }

    #[test]
    fn join_beyond_the_cap_is_a_config_error_not_a_file() {
        let err = resolve_join(
            std::path::Path::new("m.py"),
            &JoinDecl::Uniform(MAX_JOIN_BLANK_LINES + 1),
        )
        .expect_err("a typo must not reach the output");
        assert!(matches!(err.kind, crate::pipeline::PipelineErrorKind::InvalidConfig));
    }
}
